# Game Framework 2D

Первый этап модульного движка на C++20 для Windows x64. **Engine** собирается как статическая библиотека, **Sandbox** запускает оригинальный платформер Signal Below и пошаговый бой The Vault. Подробности о границах модулей, библиотечных зависимостях и следующих этапах описаны в [архитектуре](Docs/Architecture.md).

## Сборка

Нужны Visual Studio 2022 или 2026 с рабочей нагрузкой **«Разработка классических приложений на C++»**, Windows SDK и **C++ CMake tools for Windows**. Для генератора VS 2022 нужен CMake 3.24 или новее, для генератора VS 2026 — CMake 4.2 или новее. На компьютере для запуска требуется драйвер с OpenGL 3.3 Core или выше. [Генератор VS 2022](https://cmake.org/cmake/help/latest/generator/Visual%20Studio%2017%202022.html), [генератор VS 2026](https://cmake.org/cmake/help/latest/generator/Visual%20Studio%2018%202026.html).

Открой эту папку в Visual Studio как CMake-проект и выбери `Sandbox` как цель запуска. Прежнее решение `../game_framework.slnx` также вызывает CMake и запускает `Sandbox.exe`.

Из Developer PowerShell в папке с этим README выполни команды для Visual Studio 2026.

```powershell
cmake --preset windows-vs2026
cmake --build --preset vs2026-debug
ctest --preset vs2026-debug
.\out\build\windows-vs2026\Debug\Sandbox.exe
```

Для VS 2022 используй пресеты `windows-vs2022` и `vs2022-debug` с установленным MSVC v143. У обеих версий есть пресеты `vs2022-release` и `vs2026-release`. В VS Code можно выбрать те же пресеты через расширение CMake Tools. [GLFW 3.5.1 и GLAD 2.0.8](ThirdParty/README.md) входят в проект. CMake проверяет контрольную сумму архива GLFW.

Если `nasm.exe` доступен при первой конфигурации Windows x64, CMake подключит SSE-ядро фильтрации AABB. В остальных случаях используется эквивалентная функция C++. Если установил NASM после первой конфигурации, задай `-DCMAKE_ASM_NASM_COMPILER=C:/путь/к/nasm.exe` или настрой новый каталог сборки. Опция `-DGF_ENABLE_NASM=OFF` позволяет явно проверить C++.

## Sandbox

По умолчанию Sandbox запрашивает OpenGL 4.6 Core и при отказе драйвера пробует 3.3 Core. Заголовок окна показывает FPS и время кадра в миллисекундах с учётом VSync и ограничения частоты. `sandbox.log` в рабочей папке содержит диагностику запуска, контекста и ошибок.

| Управление | Действие |
| --- | --- |
| F1 | Signal Below. Собери пять кристаллов и доберись до ретранслятора |
| A / D или ← / →, Space / W / ↑ | Движение и прыжок |
| F2 | The Vault. Победи стража в пошаговом бою |
| 1, 2, 3 или мышь | Удар, защита и ремонт в бою |
| F3 / R | Показать коллайдеры / перезапустить сцену |
| P / F11 / Esc | Пауза / полноэкранный режим / выход |

## Публичный API

Приложение подключает библиотеку `Engine` через `target_link_libraries(МояЦель PRIVATE Engine)` и передаёт сцену в `Application::run`. Общий цикл и игровая логика находятся в разных целях сборки.

```cpp
#include <Application.hpp>

class MyScene final : public gf::Scene
{
public:
    void render(gf::Renderer& renderer, float, bool) const override
    {
        renderer.quad({180, 140, 120, 100}, gf::Color::hex(0x68D9AA));
    }
};

int main()
{
    gf::Application app("My Game");
    app.run(std::make_unique<MyScene>());
}
```

- [Application и Scene](engine/Application.hpp) управляют окном, VSync, паузой, фиксированными шагами 120 Гц и переменным обновлением. `frameStats()` возвращает FPS, время кадра и счётчики шагов. `WindowOptions` задаёт видимость, VSync, предел FPS и журнал.
- [Input](engine/Input.hpp) сохраняет короткое нажатие до следующего шага, отличает его от удержания, сбрасывается при потере фокуса и возвращает позицию мыши в координатах логического холста.
- [Logger](engine/Logger.hpp) принимает шесть уровней через `write()`. Он пишет в консоль и, если задан путь, добавляет строки в файл. Переданный в `WindowOptions` журнал должен жить дольше `Application`.
- [Renderer](engine/Renderer.hpp) предоставляет прямоугольники, текстуры, слои и спрайты. [World](engine/World.hpp) хранит трансформации и необязательные компоненты. Окно владеет контекстом, рендерер освобождает GPU-объекты до уничтожения окна.

При разработке сцены `update` обрабатывает игровой ввод перед физикой, `afterPhysics` подходит для проверки цели и триггеров после перемещения, `variableUpdate` получает время кадра, а `render` рисует состояние. [Платформер](demo/Platform.cpp) использует все основные компоненты сцены, [бой](demo/Combat.cpp) показывает ввод и переходы состояний.

## Проверки первого этапа

| CTest | Команда Sandbox | Проверка |
| --- | --- | --- |
| `Engine.Logic` | `--self-test` | Маски AABB, физика, модель ввода, объекты и прохождение обеих сцен. Графический контекст не нужен |
| `Sandbox.Loop` | `--smoke-test` | GLFW, фиксированные и кадровые обновления, FPS, завершение и повторное создание контекста |
| `Sandbox.OpenGL` | `--render-test` | Контекст с запросом 3.3, GLAD, пиксели текстуры и обеих сцен |

Графические тесты требуют доступного рабочего стола и драйвера. Для машины без них настрой CMake с `-DGF_ENABLE_GRAPHICS_TESTS=OFF` или запусти `ctest --preset vs2026-debug -LE graphics`. Команда `Sandbox.exe --benchmark` сравнивает AABB с эталоном C++ и выводит ускорение, если активен NASM. Замер относится к фильтрации AABB на тестовом наборе.

Целевая проверенная платформа первого этапа — Windows x64. В текущей реализации загрузка изображений использует WIC. Прототип физики обрабатывает динамические тела и статические прямоугольники. Следующий этап выделяет `Camera2D`, развивает API `Renderer2D` и добавляет индексную геометрию.
